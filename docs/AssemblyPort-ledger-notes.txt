AssemblyPort ledger notes -- why open rows do not apply, and what they need from outside src/Mod/Assembly
Companion to docs/AssemblyPort-ledger.tsv. Created 2026-10-22 on AssemblyPort at fe871ff48c, upstream/main d3f4da791d.

How these were derived
- fwd (ledger column): git apply --check --cached of the in-scope patch (translations excluded) against the
  index, which equals HEAD. --cached because the working tree is CRLF and the index LF.
- To tell a real dependency from fork-side context, each failing patch was also checked against two other
  trees, through a throwaway GIT_INDEX_FILE: upstream's baseline 17f203e118 ("base") and the port
  759cd15c9c ("port"). It fails at base -> it needs an earlier upstream commit. It applies at base but not at
  the port -> the port's adaptations are in the way. It applies at the port but not at HEAD -> fork commits
  since the port are in the way.
- Trial three-way picks: git merge-tree --write-tree --merge-base=<c>^ HEAD <c> ("solo"), and the same in
  ledger order with each clean pick advancing a simulated tip ("chain"). No ref, index or worktree was
  touched. "N hunks" below is the conflict-marker count it left in scope.

Cross-module dependencies, by API
- App::LocalCoordinateSystem / App::DatumElement (App/Datums.h): here now (2507fde4bc; App::Origin derives from LocalCoordinateSystem, App::OriginFeature is an alias of DatumElement, Part::LocalCoordinateSystem exists). The port's Origin/OriginFeature spellings are obsolete. Worse, App::Origin-only checks miss Part::LocalCoordinateSystem, which upstream's LCS checks catch. Reverting them to upstream's spelling removes conflicts (67103b19c9) and fixes that gap.
- Gui::SoTransformDragger subsystem: here (f8b6a242f7, used since b223d1b31a). No open row needs more of it.
- fastsignals: here (f0731ef531). Upstream's scoped_connection members in 8e04c56f27/44c3ea8b00 compile as-is.
- Base::Color: here; App::Color is an alias of it (src/App/Color.h:42). The port's App::Color spellings could go back to Base::Color.
- Console naming: the fork has upstream's lowercase warning/error/log as well as the capitalised forwarders, so the port's Warning/Error/Log renames are now just conflict sources (62544c4c6e, 67103b19c9).
- std::format logging: missing. The fork's Console is printf (fmt::sprintf). Blocks 8a1bdba1dd and 62544c4c6e.
- Quantity::getUserString: returns std::string here now; the port's .toStdString() is already gone.
- Gui/Selection/: here, with Gui/Selection.h kept as a forwarding shim; upstream's <Gui/Selection/Selection.h> works again. SoFCSelectionAction.h has not moved, so that include stays adapted.
- Control().activeDialog(App::Document*): here, so upstream's activeDialog(nullptr) compiles again.
- Measure: no open row uses it.
- PartApp::LinkArray and SuppressibleExtension on LinkElement: missing (see 67103b19c9).
- Build macros: disable_occt8_deprecation_warnings, target_compile_warn_error and the new SET_BIN_DIR signature are all missing; they arrive only with upstream's cMake/FreeCadMacros.cmake changes.
- Adaptations that stay fork-only: Gui::ViewerContext in place of View3DInventorViewer in the edit API (fe9c9139fb), ViewParams as a static API, PropertyXLink::setValue(obj, subs) in place of the protected setSubValues, ViewParams::getDefaultShapeColor() in place of MaterialAppearance::getDefaultAppearance(), AssemblyParams defaults, and the fork's mapped-name, Part::Datum and connection-lifetime fixes.
